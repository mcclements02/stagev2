cAIrn

You add one stone. You don’t rearrange the others.

What it is.

Put more than one AI coding agent on a repo and the problem isn’t bad code. It’s stranded work. One agent finishes something on a branch nobody knows about, another builds it again, a third rewrites the first one’s fix. cAIrn is one rule: every commit that touches code also updates a shared ledger in the repo. The next agent reads it before it starts.

What I did

I was already running this protocol across 13 of my own private repos. cAIrn is that, pulled out into one command anyone can install.

What went wrong

On a Mac, asking whether Scripts/ exists says yes even when the folder is really scripts/. The installer rewrote files on every run until I made it ask git which spelling was real.

01

A conflict is the signal

One row per branch and an append-only log. If two agents collide in the log, that’s the point. Keep both entries.

02

The hook is a reminder, not a gate

--no-verify exists and agents will find it. The check that counts runs on the pull request.

03

No vendor

One Bash script. It doesn’t care which lab made the agent. macOS, Linux, and Windows through Git Bash or WSL.
